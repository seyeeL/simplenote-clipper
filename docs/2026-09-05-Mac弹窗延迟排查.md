# Mac 上点击图标后弹窗延迟

更新日期：2026-09-05。

## 先区分慢在哪一步

- 点击工具栏图标后，整个窗口过一段时间才出现：排查弹窗页面加载和浏览器调度。
- 窗口已出现，点击「剪藏本页」后等待：排查正文提取、图片转存和 Simplenote 写入。

扩展没有设置点击图标后等待一秒的定时器。正文提取和上传在点击「剪藏本页」后才开始。

## 浏览器侧的已知问题

Chromium 已有 [Mac 扩展弹窗冷启动延迟的缺陷报告](https://issues.chromium.org/issues/549552319)：
浏览器空闲后首次打开可能很慢，紧接着再次打开却很快；不含 service worker 或网络请求的
最小扩展也有报告。症状会随时间波动，连续点击几次变快不能单独证明问题已修复。

[Chromium 的弹窗实现](https://chromium.googlesource.com/chromium/src/+/main/chrome/browser/ui/views/extensions/extension_popup.cc)
会等待页面加载完成再显示窗口。因此，页面开始执行之前的浏览器调度等待，也会表现为
「点击图标没反应」。遇到相似症状仍需实测，不能仅凭操作系统或延迟长短认定是这个缺陷。

## 临时验证加载优先级

`PMLoadingPageVoter` 是 Chromium 的加载优先级机制，
[实现见源码](https://chromium.googlesource.com/chromium/src/+/main/components/performance_manager/execution_context_priority/loading_page_voter.cc)。
它可用于对照排查，效果与浏览器版本有关。

先保存网页中未提交的输入，完全退出浏览器，再选择对应命令重新打开：

```bash
# Google Chrome
open -a "Google Chrome" --args --enable-features=PMLoadingPageVoter --restore-last-session

# Brave
open -a "Brave Browser" --args --enable-features=PMLoadingPageVoter --restore-last-session

# Brave Origin
open -a "Brave Origin" --args --enable-features=PMLoadingPageVoter --restore-last-session
```

这只给本次浏览器进程传入参数，不修改永久配置。浏览器未完全退出时，命令可能只打开一个
窗口而没有应用参数；可在 `chrome://version` 或 `brave://version` 的「命令行」中核对。
不要公开整段命令行或配置页截图，其中可能包含个人路径等信息。

测试应包含空闲约两分钟后的第一次点击，并在不同时间重复。仍然慢时，记录浏览器和
macOS 版本、冷启动与连续打开的差别，以及其他扩展是否同样受影响，再继续定位。
要结束对照，完全退出浏览器后按平常方式打开即可。
