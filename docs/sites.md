# 站点兼容清单

这个扩展默认走通用启发式提取正文，大部分文章页不用配置就能抓。这里记的是**实测过**
的站点：哪些验证通过、哪些写了专用规则、哪些还有已知缺口。

## 兼容域名

写了专用规则、并且实测通过的站点。这份编号清单只放站点，加一个站点就加一条。

1. **[微信公众号](#微信公众号)** `mp.weixin.qq.com`：普通图文、纯文字分享、贴图型（图片消息）三种版式，
   正文、配图、作者、时间全部通过。
2. **[微博](#微博)** `weibo.com`、`weibo.cn`：正文、作者、时间、九宫格配图全部通过。
3. **[小红书](#小红书)** `xiaohongshu.com`：正文、作者、时间、九宫格配图全部通过；**要登录态**。
4. **[X（推特）](#x推特)** `x.com`、`twitter.com`：推文正文、配图、视频封面、引用推文、作者、时间
   全部通过；剪的是你点开的那一条，回复和互动数字不进笔记。

> 不在这张清单上的站点走[通用启发式](#验证过但不需要专用规则的站点)，不用配置也能抓。
> `lib/domains.js` 里另有[二十来个域名只配了标签](#只配了标签的域名)，提取没验证过，别当成支持。
> 想加新站点看[加一个新站点](#加一个新站点)。

## 写了专用规则的站点

### 微信公众号

`mp.weixin.qq.com`

| 项 | 取法 |
|----|------|
| 正文 | 普通图文和纯文字分享 `#js_content`；贴图型 `#js_image_desc` |
| 配图 | 贴图型 `#page_top_area .swiper_item_img`，排在文字后面 |
| 作者 | `#js_name`，分享型页面退到 `#js_wx_follow_nickname` |
| 时间 | `#publish_time` |
| 标签 | `公众号` |

实测三种版式各一条：

| 版式 | 样例 | 结果 |
|------|------|------|
| 普通图文 | [视频译介：简化生活](https://mp.weixin.qq.com/s?__biz=MzUyMjk0NDU4NA==&mid=2247498584&idx=2&sn=8c4884aefbc0c1216e3bba34f9feb53f&scene=142) | 147 字符正文 |
| 纯文字分享 | [一个人状态变差…](https://mp.weixin.qq.com/s/QpoEDH56bWI_7P6WjJu7KQ) | 791 字符正文 |
| 贴图型 | [“1:7:2”法则](https://mp.weixin.qq.com/s/7f0LRUthj0_h_20aaoe_OA) | 文案 + 1 张图 |

前两条实测 2026-08-20，贴图型 2026-08-25。作者和时间三条都对。

踩过的坑：这个站点会把整篇正文放在 `<p class="share_notice_inner">` 里。噪声过滤规则里
有 `share` 这个词，早期版本按类名一刀切，正文从 847 字符掉到 44。现在噪声词分强弱两档，
弱证据的词只在文字量小或链接密度高时才删。

另一个坑：公众号排版大量用 `<div>` / `<section>`，一个 `<p>` 都没有。按段落打分选容器
会得 0 分，转 Markdown 时也会把全文拼成一整行。两处都单独处理过了。

第三个坑：有些文章整篇正文塞在一个 `<h1>` 里（编辑器里选了个「标题样式」的模板就会这样，
实测 [自由职业成功的星盘是什么样的？](https://mp.weixin.qq.com/s/HWErVfc6E3PzopX5jJYDQw)，
2026-08-27）。标题必须压成一行（`#` 后面换行就断了），于是 3000 字挤成一坨。这不是站点
规则能救的 —— 同一个域名下大部分文章的 `<h1>` 就是正常标题，不能按站点一刀切。走 popup
的「移除 Markdown 格式」：勾上之后标题按普通块渲染，段落分行就回来了（见 README）。

#### 贴图型（图片消息）

`page_type: 2` / `item_show_type: 8` 那种版式：几张大图配一段文案，正文里一个段落标签都
没有。DOM 和普通图文完全是两套，一条一条对应：

| 坑 | 表现 | 规则 |
|----|------|------|
| 文案和图片分家 | 文案只有 `#js_image_desc` 一段，图片在页面顶部的 swiper 里，两块没有共同的正文容器 | `root` 里分别点名，文字在前 |
| `#js_content` 变了内容 | 这种页面上 `#js_content` 装的是赞赏面板，整块收进来正文会变成「微信扫一扫赞赏作者」 | `#js_content:not(:has(#js_image_content))` |
| 占位 swiper | 顶上还有个 `aria-hidden` 的占位 swiper，装着同一张首图 | 图片选择器限定在 `#page_top_area` 下 |
| 短文案被当噪声 | 文案挂在 `p.share_notice` 上，命中弱证据词 `share`，一两句话又够不着 200 字保命线，整块被删 | `keep: ['#js_image_desc']` |
| 没有 `#js_name` | 分享型页面的号名只在关注条上，`meta author` 还经常是空串 | `author` 补上 `#js_wx_follow_nickname` |

**两条路必须互斥。** `#js_image_desc` 套在 `#js_content` 里，两个选择器都命中的话，`root`
的嵌套去重只会留下最外层的 `#js_content`，文案反而丢了。`:not(:has(#js_image_content))`
就是让普通图文那条路在贴图页上不命中。

**图片一次全在 DOM 里。** 五张图的贴图页实测渲染出五个 `.swiper_item_img`，`src` 都是
真地址，没有懒加载占位，也没有 swiper 循环滚动的复制品（和小红书相反）。

**不用换原图地址。** 页面上的 `src` 带 `tp=webp`，和数据里的 `cdn_url` 是同一张图的两种
编码：实测 1242×1660 完全一致，webp 88 KB、jpeg 145 KB。webp 更小，直接用页面上那个。

### 微博

`weibo.com`、`weibo.cn`（子域自动继承）

| 项 | 取法 |
|----|------|
| 正文 + 配图 | `.wbpro-feed-content`，兜底 `[class*="wbtext"]` |
| 作者 | `a[class*="_name_"][href*="/u/"]` |
| 时间 | `a[class*="_time_"]`，两位年份补成四位、月日补零 |
| 标题 | 微博没有标题，取正文开头 40 字 |
| 图片 | 缩略图尺寸段换成 `large`（原图） |
| 标签 | `微博` |

实测 2026-08-20 两条：[纯文字](https://weibo.com/1088413295/5113631702256640)483 字符正文；
[带两张配图](https://weibo.com/2954851423/5331427143191023)正文 + 2 张图，作者和时间都对。
两条都不需要登录，headless 直接能渲染。

微博的类名带构建 hash（`_wbtext_1h76l_19`），只匹配稳定的那一段，否则一发版就失效。
时间显示成 `26-8-13 12:19` 这种两位年、月日不补零的格式，规则里补成 `2026-08-13`。
表情是 `<img>`，混进正文会被当成配图，开了图床还会一张张传上去，所以按 `src` 过滤掉。

**配图靠外层容器一起带出来。** 正文块 `[class*="wbtext"]` 和九宫格 `div.picture` 是兄弟节点，
共同的父节点 `.wbpro-feed-content` 不带构建 hash，直接拿它当 `root`，文字和图按页面顺序
一起进正文。`wbtext` 留在 `root` 数组里兜底：外层哪天改名了，至少正文还在——两个选择器
在正常页面上是嵌套关系，只会保留最外层那个，正文不会重复。

**图片要 Referer 才给。** sinaimg 认「浏览器 UA + 没有 Referer」这个组合就 403，跟图片
尺寸无关（`orj360` 一样被拒）。service worker 抓图正好是这个组合，所以微博的图在配上
`imageReferer` 之前根本转存不进图床。规则里配了 `imageReferer: 'https://weibo.com/'` 和
`imageHosts: ['sinaimg.cn']`，抓图期间临时装一条 declarativeNetRequest 会话规则补上 Referer。

**九宫格给的是缩略图。** 页面上的 `src` 是 `orj360`（本文那两张各 14 KB），截图缩到 360 宽
根本看不清字。规则里把地址的尺寸段换成 `large` 拿原图（同一张 477 KB）。只认
`orj360` / `mw690` / `bmiddle` 这类已知尺寸段，头像的 `crop.0.0.1080.1080.180` 不在其中，
不会被误改。

### 小红书

`xiaohongshu.com`

| 项 | 取法 |
|----|------|
| 正文 + 配图 | `#detail-desc` + `.media-container`，文字在前图片在后 |
| 标题 | `#detail-title`，没有就取正文开头 40 字 |
| 作者 | `#noteContainer .author-wrapper .name` |
| 时间 | `__INITIAL_STATE__` 里的时间戳，兜底才用 `.bottom-container .date` |
| 标签 | `小红书` |

正文排在图片前面：一条笔记最多九张图，图放前面要翻很久才看得到文案。

实测 2026-08-20 五条笔记（图文 / 视频 / 有标题 / 无标题 / 带表情各一条），正文、作者、
时间、九宫格配图都对。

**必须在登录态下用。** 干净 profile 打开笔记页会被风控挡掉，跳转到
`website-login/error?error_code=300012`（「IP存在风险，请切换可靠网络环境后重试」）。
扩展跑在你自己已登录的浏览器里，所以剪藏没问题；但 `tools/probe.mjs` 起的是独立
profile，抓小红书只会拿到那张拦截页，调试得连已登录的浏览器（见
[调试某个站点抓不到正文](../README.md#调试某个站点抓不到正文)）。

这个站点一次踩了五个坑，规则里每一条都对应一个：

| 坑 | 表现 | 规则 |
|----|------|------|
| swiper 循环滚动 | 九张图的 DOM 里有 11 个 `<img>`，首尾两张各复制一份 | `drop: .swiper-slide-duplicate` |
| 图区的 UI 文字 | 「1/9」页码、翻页箭头、长按保存提示混进正文 | `drop: .fraction / .arrow-controller / #copy-img-guide` |
| 视频笔记 | 西瓜播放器把「00:00 倍速 2x 1.5x 请刷新试试」写进正文 | `drop: .player-container` |
| 正文表情 | 表情是 `<img>`，开了图床会一张张传上去 | `drop: img.note-content-emoji` |
| 话题标签 | `<a href="/search_result?...">#刘亦菲</a>`，转成 markdown 是一串点不开的相对链接 | `unwrap: a.tag` |

还有两处不是靠删能解决的：

**正文分段靠文本里的换行。** 小红书正文的段落是 `\n` 加 CSS `white-space`，HTML 里既没有
`<p>` 也没有 `<br>`。按通用规则换行只是排版空白，会被压成空格，整篇文案挤成一行。
`keepLineBreaks: ['#detail-desc']` 让这个容器里的换行转成 `<br>`，收口时再变回段落。
别的站点不要开这个：普通 HTML 里的换行确实只是排版。

**话题标签里夹着 `[eoi]`。** 页面上渲染成一个小图标，取 `textContent` 就露出来了，
`#披荆斩棘的哥哥[eoi]#`。它和正文 `<span>` 长得一模一样，选择器区分不了，只能按文本抹掉
（`stripText: [/\[eoi\]/g]`）。

**页面上只有相对时间。** `.date` 显示的是「6天前」「7小时前」，存进笔记一年后再看毫无意义。
两条弯路都走不通：`.date` 元素没有带绝对时间的 `title` 属性；页面里的 JSON-LD 虽然有标准的
`datePublished` 字段，但那个值是**页面渲染时间**（实测就是当下这一秒），拿来当发布时间是错的。

真正的时间戳在 SSR 塞进 `<script>` 的 `window.__INITIAL_STATE__` 里（`"time":1786632183000`，
毫秒）。规则的 `publishedFrom` 从 script 的 textContent 里正则取，锚到 `"noteDetailMap"` 那段
再往后找第一个 `"time"`，取不到就退一步按 URL 里的笔记 id 定位。不从整段头上找：state 里
还带着推荐流，第一个 `"time"` 未必是这条笔记的。

实测四条对照页面显示：「6天前」→ 2026-08-13、「5天前」→ 2026-08-15、「07-28」→ 2026-07-28、
「7小时前」→ 当天 13:12，全部吻合。

**图片地址不要改。** URL 长这样：

```
https://sns-webpic-qc.xhscdn.com/<时间戳>/<hash>/notes_pre_post/<id>!nd_dft_wlteh_webp_3
```

结尾那段是图片处理参数，横图是 `wgth` 竖图是 `wlteh`。实测换成别的参数、或者去掉整段，
一律 403，签名是绑参数的，只有页面上给的那一个能用。

路径里那段 `202608201652` 是签发时间：**每次重新打开笔记页，同一张图拿到的 URL 都不一样**
（隔 18 分钟再开就变成了 `202608201710`）。旧那条 18 分钟后仍然能取，更长的时效没验证。
这种地址不适合长期躺在笔记里，要留着建议开图床转存。

不需要 Referer（和微博相反），完整 URL 裸请求就是 200。

### X（推特）

`x.com`、`twitter.com`（子域自动继承）

| 项 | 取法 |
|----|------|
| 主推 | 按 URL 里的推文 id 框出那一个 `<article>`（`scope`），后面所有选择器都只在这块里找 |
| 正文 | 新版 `div[dir="auto"]`，老版 `[data-testid="tweetText"]`，两条互斥 |
| 配图 | `img[src*="twimg.com/media/"]`，尺寸档换成 `large` |
| 视频 | 存不进笔记，留 `<video>` 的封面图（`videoPoster`） |
| 引用推文 | 嵌在主推里的另一个 `<article>`，重排成「抬头 + 正文 + 配图」再套成引用段（`blockquote` + `formatQuote`） |
| 作者 | 昵称那个指向个人页的链接，老版退到 `[data-testid="User-Name"]` |
| 时间 | 时间戳链接的文字，切掉中间点前面的时分 |
| 标题 | 推文没有标题：`作者 on X: 正文开头 40 字`（`titleFormat`） |
| 回复 | 主推底下的串和评论，一条一段引用（`**昵称 @handle** · [日期](链接)` + 正文），popup 里「同时剪藏评论」默认勾着（`replies`） |
| 标签 | `推特` |

实测 2026-08-25，未登录状态（下面「两代前端」那一节说为什么要强调这个）：

| 版式 | 样例 | 结果 |
|------|------|------|
| 视频推 | [发现一个很酷的动效库](https://x.com/yyyole/status/2091554005772321204) | 文案 + 视频封面，205 字符 |
| 图文推 | [DGX Spark 的最大对手](https://x.com/yyyole/status/2092082347391033806) | 文案 + 1 张图 |
| 引用推 | [很多朋友在问如何搞定电商图](https://x.com/yyyole/status/2002724036355240392) | 文案 + 2 张图 + 引用段（引用里还带 4 张图） |
| 串里的一条 | [地址在这里](https://x.com/yyyole/status/2091554008418939048) | 只有这一条，上文那条不进来 |
| 带链接卡片 | [OpenAI 那条](https://x.com/OpenAI/status/2089777845187031262) | 文案 + 外链，卡片不收 |

作者和时间五条都对。`https://twitter.com/...` 和配图页那种 `/status/<id>/photo/1` 的 URL 一起验过，
走的是同一条路。

**先框出「哪一条是主推」，再谈选择器。** 推文详情页上，上文、主推、回复是一排长得一模一样的
`<article>`，引用推文还会在主推里再嵌一层。光靠选择器分不出哪个是用户点开的那条 —— 早期版本
不框范围，剪出来是整页：登录/注册按钮、三条推、每条的头像和「转推 收藏 Views」全在里面
（1355 字符，其中主推正文只占 100 出头）。

规则里的 `scope` 按 URL 里的推文 id 找那条**时间戳链接指向自己**的 article。两个坑：

- 点开的是串里的第二条时，上文排在它前面，不能按「第一个 article」取。
- 有人引用了主推时，那条回复的引用块里也有一个指向主推的链接。所以只认最外层 article 里
  「自己的」链接（`link.closest('article') === article`），按 `closest` 一路往上找会框到回复上去。

框不出来（改版了、或者剪的是主页/时间线这种没有推文 id 的页面）就退回整页按规则收：剪出来是
当前可见的一串推文，不算对，但比整页走通用启发式强。

**两代前端。** 2026 年 8 月的 x.com 是一套服务端渲染的 Tailwind 页面，整页一个 `data-testid`
都没有，正文是 `div[dir="auto"]`；老版 React 页面（`#react-root` + `data-testid="tweetText"`）
的选择器也一并写着兜底。两条路必须互斥：老版页面上 `dir="auto"` 满天飞（昵称、卡片标题都是），
一起收会带进一堆噪声，所以新版那条挂了 `:not(article:has([data-testid="tweetText"]) *)` ——
页面上有 `tweetText` 就说明是老版，这条不生效。

上面那五条都是在未登录的新版页面上验的。**登录态下如果 X 给的还是老版页面，兜底选择器只保正文、
配图、作者、时间，引用推文不会划成引用段**（老版的引用块是 `div[role="link"]` 不是嵌套 article，
会跟主推正文接在一起）。真遇到了照[加一个新站点](#加一个新站点)的步骤把老版的选择器补上。

其余几个坑，规则里每条对应一个：

| 坑 | 表现 | 规则 |
|----|------|------|
| 配图外面套着相对链接 | 图外面是 `<a href="/u/status/123/photo/1">`，`unwrap` 按 textContent 脱会把 `<img>` 一起脱没 | `unwrap` 改成保留子节点，不是保留文字 |
| @某人 / #话题 | 指向站内相对地址，转成 markdown 是一串点不开的链接 | `unwrap: a[href^="/"]` |
| 视频 | `src` 是 `blob:`，html2md 整棵丢掉，正文只剩一段文字 | `videoPoster: true`，换成封面图 |
| 引用推文 | 它的正文接在主推后面，读起来像同一个人说的 | `blockquote: ['article']` |
| 引用推文整块收是碎行 | 昵称、`@handle`、时间各占一行，和评论那边两种版式 | `formatQuote`，拼成和评论一样的抬头 |
| 头像 | 引用推文头上那张 `profile_images` 会当配图存下来 | `drop: img[src*="profile_images"]` |
| 缩略图 | 页面上给的是 `name=small` / `name=medium` | 尺寸档换成 `large` |
| 视频封面进两次 | 底下垫着的占位 `<img>` 和 hydrate 之后 `<video>` 的 poster 是同一张，两个选择器都得留 | `dedupeImages: true` |

**换图只动 `name`，不动 `format`。** 实测同一张图：`format=webp&name=small` 19 KB、`medium`
40 KB、`large` 95 KB，`format=jpg&name=orig` 360 KB —— 但 **`format=webp&name=orig` 直接 404**，
orig 只有 jpg 给。所以只把尺寸档换成 `large`，格式保持页面上那个。不需要 Referer，裸请求就是 200。

**回复默认剪，可以取消。** 推特很多内容是一串（作者接着自己发几条），只剪第一条等于剪了半句话，
所以 popup 上「同时剪藏评论」默认勾着 —— 这个勾选框只在写了 `replies` 的站点上露面，别的站点看不到。
右键菜单没有勾选框，走的也是默认（剪）。回复接在正文后面，中间用 `---` 隔开，抬头一句
`## Comments` 说明底下这串是什么：

```
---

## Comments

> **撸毛吃猪脚饭| 美股合约首选Gate @mnmn94253156337** · [2026-08-07](https://x.com/mnmn94253156337/status/2085627066423406716)  
> 不错 办u卡必备

> **CatNarratives老三 @laosanhemao** · [2026-08-07](https://x.com/laosanhemao/status/2085628970486083659)  
> 老师这个整理真的用心了
> > **蜘蛛侠 | 1000X GEM @zhizhuxia22** · [2026-08-07](https://x.com/zhizhuxia22/status/2085629389279256719)  
> > 谢谢老师
```

一条回复都没有时抬头也不出现，笔记末尾不会挂一个空的 `## Comments`。

**版式对齐 Obsidian 官方剪藏器。** 抬头行、日期、嵌套引用这几样跟
[defuddle](https://github.com/kepano/defuddle)（obsidian-clipper 用的提取库）的
`src/extractors/twitter.ts` + `src/utils/comments.ts` 一致：一条评论一段引用，
`**昵称 @handle** · [日期](原推链接)` 一行抬头，正文和配图跟在下面，回复某条评论的那条
套进它的引用段里。同一份笔记两边剪出来长得一样，换工具不用重排。

抬头和正文之间只换一行（markdown 的硬换行，抬头行尾留两个空格），不另起一段；楼中楼那层
引用段前面也不留空行（`html2md` 里做的）。都是同一个理由：另起一段会在引用段里攒出孤零零
一行 `>`，一条带回复的评论要占五行。引用段本来就能打断段落，不留空行照样是嵌套。

**引用推文用同一套抬头**（`formatQuote`）。整块收进来的话昵称、`@handle`、时间各占一行，
和评论那边是两种版式；现在两处都是「抬头 + 正文 + 配图」。

有一处故意和 defuddle 不一样：**日期挂链接**。defuddle 的引用块日期是纯文字，那条推的
地址就此丢了；这边评论和引用推文的日期都链回原推，笔记里点得开。

**一条回复只挑五样东西，不整块收 `<article>`。** 整块收的第一版实测下来不能看：昵称、`@handle`、
时间、正文、阅读数各占一行，一条回复七八行，十几条读下来全是碎片，阅读数（`11K`、`7.2K`）
还混在里面像是正文的一部分。现在只挑昵称、`@handle`、时间、正文、配图五样，规则自己拼出那段引用，
其余（头像、阅读数、转推收藏那排按钮）一概不要。配图各自成段跟在正文后面，多行的回复保留它自己的换行。

拼块的代码在 `lib/site-rules.js` 的 `commentBlock`：`replies` 返回的不一定是页面上的现成元素，
自己 `createElement` 拼一个出来也行，引擎照样把它接进正文。正文搬的是子节点不是整块 —— 正文在
页面上是个 `div`，整块塞进来会多套一层。

**日期从推文 id 里算。** 页面上那句时间不能直接存：新版只有「8月7日」这种没有年份的写法，
一年后再看不知道是哪年的，更早的还会显示成「8h」。推文 id 是 snowflake，高位就是发布毫秒数
（`(id >> 22n) + 1288834974657`），算出来的日期和页面显示的对得上（实测
`2085627066423406716` → 2026-08-07，页面上就是「8月7日」；主推那条时间戳写着「15:19 · 2026年8月7日」，
UTC 07:19 加八小时正好）。老版页面有 `<time datetime>` 就直接用它。两条路都算不出来才退回页面上那句原文。

日期按**本机时区**换算 —— 登录态下页面显示的也是本机时区，两边对得上。未登录的 SSR 页面是
服务端渲染的，那上面的日期是 UTC：跨零点的推会比页面上的标签晚一天（实测
`2089777845187031262` 页面写「8月18日」= UTC 18:13，本机 UTC+8 算出来是 2026-08-19）。
主推自己的日期取的是页面上那句文字，所以这种页面上主推和评论的日期可能差一天。

日期后面链回那条回复自己：时间戳链接的 `href` 是站内相对地址（`/handle/status/123`），
补成绝对地址才点得开 —— 顺带躲开 `unwrap: a[href^="/"]`（相对链接一律脱成文字，绝对的
`/status/` 链接留着）。

**作者自己那串按平级排。** 主推底下先是作者接着自己发的几条（串），再是别人的评论。串在
页面结构上是一条条首尾相接的回复，照下面的分组算会一条比一条深一层 —— 实测[沐阳那条电商图的推](https://x.com/yyyole/status/2002724036355240392)
有五条串，套到第五层没法读。串本来就是正文的续集，一律平级。串到第一条别人的评论为止
（和 defuddle 的判法一致）：作者后面回自己评论区的那条算普通回复，该嵌还是嵌。

**嵌套靠页面自己的分组，两代前端各一套。** 老版（React，**登录态下就是这套**）每条推各占一个
`[data-testid="cellInnerDiv"]`：同一串的几条挨着排，串与串之间夹一个不含推文的 cell，
所以连着的 cell 逐级加深、遇到空 cell 归零（判法照搬 defuddle）。新版（SSR，未登录看到的那套）
没有 cell，一串对话包在同一个 `<li>` 里，li 里第一条是顶层评论，后面几条接着它。

两边都在真页面上验过 cell / li 的排法：

| 页面 | 前端 | 实测 |
|------|------|------|
| [蜘蛛侠那条](https://x.com/zhizhuxia22/status/2085626801058127899)（登录态） | React | 45 个 cell 23 条推；「评论 + 楼主回复」是**连着的两个 cell**（2/3、5/6、8/9），彼此之间夹空 cell |
| 同一条（未登录） | SSR | 三条评论各自一个 `li`，一条子回复都不给，出来是平铺的引用段 |
| [songkeys 那条](https://x.com/songkeys/status/2090416137720999992)（登录态） | React | cell 编号 0、2、4…… 全是隔一个，23 条评论没有一条是楼主的回复 —— 这页平铺是对的，不是漏了嵌套 |

层级跳级时按能挂上的最深一层挂，不凭空造中间层。

**只收页面上已经加载出来的回复。** X 的回复列表是滚动加载的，没往下翻就只有头几条；翻得太远的
反过来会被回收出 DOM。想多剪几条就先在页面上翻到，再点剪藏。

**回复只算主推底下的。** 主推之前的是上文（点开串里的第二条时会看到），不进笔记；回复列表底下
接着的「更多推荐」也不进。

「更多推荐」怎么切掉，两代前端不一样：新版（SSR）它在对话容器 `[id^="urt:conversation"]` 外面，
按容器过滤就行；**老版（React）没有这个容器**，推荐推和评论一样是一排 cell，早期版本那句
「不在对话容器里」在登录态下等于没设防。现在照 defuddle 的判法按边界切：cell 按文档顺序收，
收到第一个出现在 cell 之后、又不属于任何推文的 `section` / `h2` 为止。第一个 cell 之前的
不算边界 —— 页面顶上的「Post」标题和包着整个对话的 `section` 排在前面，拿它当边界会一条都收不到。

**链接卡片不收。** 卡片图在 `pbs.twimg.com/card_img/` 下，`root` 里只点名了 `/media/` 和视频封面。
卡片本来就是正文里那条链接的预览，链接还在笔记里。

## 加一个新站点

1. 先看通用逻辑够不够：

   ```bash
   node tools/probe.mjs "<url>"
   ```

   `probe.mjs` 要 Node 22+（全局 `fetch` 和 `WebSocket`），版本不够会直接报出来。

   `root` 和 `mdLen` 合理就不用写规则，直接记到「验证过但不需要专用规则」那张表。

2. 抓不对就看正文到底在哪：

   ```bash
   node tools/probe.mjs "<url>" --dump
   ```

   列出页面里文字量最大的容器。两者对不上是选容器的问题，选对了但 `mdLen` 很小是被
   噪声过滤误删了。

3. 往 `lib/site-rules.js` 加一条。字段都是可选的，只写通用逻辑搞不定的那几项：

   ```js
   {
     name: '站点名',
     hosts: ['example.com'],        // 子域自动继承
     root: '.article-body',         // 也可以传一组选择器
     author: '.byline',
     published: 'time.published',
     titleFromBody: true,           // 站点没有标题时用
     normalizePublished: (t) => t,  // 时间格式怪的时候用
     drop: ['.ad-slot'],            // 规则级的额外删除项
     title: '.post-title',          // 标题不在 og:title 里，或者 og:title 带站点名后缀
     publishedFrom: (doc, url) => '',// 页面上只有相对时间、真实时间藏在别处时用
     scope: (doc, url) => null,     // 一页上有一堆同构卡片时，先框出「点开的是哪一个」
     replies: (doc, url) => [],     // 主贴底下的回复，勾了「连回复一起剪」才收
     titleFormat: ({ body, author }) => body,  // 正文开头当标题时再包一层
     rewriteImageSrc: (src) => src, // 改图片地址（缩略图换原图之类）
     imageReferer: 'https://example.com/',  // 图片站点要防盗链 Referer 时用
     imageHosts: ['img.example.com'],       // 上面那个 Referer 补给哪些域名
     unwrap: ['a.tag'],             // 标签脱掉，里面的内容留下
     blockquote: ['article'],       // 点名的块套成引用段（引用推文这种）
     formatQuote: (doc, el) => [],  // 套引用段之前先把那块重排一遍，返回一组节点
     videoPoster: true,             // 视频换成它的封面图
     dedupeImages: true,            // 同一个地址的图只留第一次出现的那张
     stripText: [/\[eoi\]/g],        // 按文本抹掉图标占位这类脏字符
     keep: ['.short-body'],         // 短正文顶着 share / footer 这类弱证据词时豁免
     keepLineBreaks: ['.desc'],     // 正文分段靠 \n + CSS 时才开
   }
   ```

   `scope` 返回一个元素，`root` / `title` / `author` / `published` 的选择器就都只在这块里找；
   返回 null 退回整篇文档。推特详情页上主推、上文、回复是一排同构的 `<article>`，靠选择器
   分不出哪个是用户点开的那条，就是它的用武之地。

   `replies` 返回一组元素，接在正文后面（中间自动插一条 `---`），只在勾了「同时剪藏评论」时收。
   写了这个字段的站点，popup 上才会出现那个勾选框。返回的元素不必是页面上现成的，规则可以
   自己 `doc.createElement` 拼（推特就是这么把一条回复拼成一段引用的）。

   `formatQuote` 拿到被 `blockquote` 点名的那个块，返回重排好的一组节点顶替它；返回空
   或者抛错就还用原块，不至于把整块内容弄丢。它跑在 `unwrap` **之前** —— 重排要认昵称
   和时间戳链接，`unwrap` 一跑那些链接就被脱成纯文本了。

   `blockquote` 和 `keepLineBreaks` 的选择器是在**收进正文的那份克隆体**上匹配的：`root` 收了
   哪几块，克隆体里就只有那几块，页面上的祖先节点不在里面（推特收的是引用推那个 `article`，
   所以写 `article` 而不是 `article article`）。

   字段都是可选的。`title` / `titleFromBody` 可以一起写：优先用选择器，取不到再退回
   正文开头（小红书的笔记有的有标题有的没有，就靠这个组合）。

   `root` 传数组时是**并集**：命中的块按顺序拼成一个容器。互相嵌套的只留最外层，
   所以「主选择器 + 兜底选择器」这种写法不会把正文收两遍。

   同一个域名下有几种版式、选择器会互相嵌套时（公众号的贴图页和普通图文），用
   `:not(:has(…))` 把它们写成互斥的：嵌套去重只留最外层，两条路都命中的话里层那块就丢了。

4. 需要新标签就再改 `lib/domains.js`。

5. 跑一遍测试，再回来更新这份文档：

   ```bash
   node --test "tests/*.test.mjs"
   ```

## 注意

`lib/extract.js` 依赖 `lib/site-rules.js`，而 `extract.js` 是注入到页面里动态 `import()` 的。
拆出新模块时记得同步加进 `manifest.json` 的 `web_accessible_resources`，否则页面取不到文件，
扩展直接报 `ReferenceError`。
